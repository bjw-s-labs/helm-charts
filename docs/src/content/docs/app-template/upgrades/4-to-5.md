---
title: "Upgrading from v4.x to v5.x"
description: "Instructions for upgrading from v4.x to v5.x of the app-template chart"
---

This release introduces a breaking change to the `rawResources` configuration structure.

## rawResources restructure

The `rawResources` configuration has been restructured to use a `manifest` wrapper. This brings raw resources in line with standard Kubernetes manifests and improves how labels and annotations are handled.

### Before (v4)

```yaml
rawResources:
  validating-webhook:
    enabled: true
    apiVersion: admissionregistration.k8s.io/v1
    kind: ValidatingWebhookConfiguration
    name: my-webhook
    labels:
      app: my-app
    annotations:
      description: "My webhook"
    spec:
      rules:
        - apiGroups: [""]
          apiVersions: ["v1"]
          operations: ["CREATE"]
          resources: ["pods"]
          scope: "Namespaced"
```

### After (v5)

```yaml
rawResources:
  validating-webhook:
    enabled: true
    manifest:
      apiVersion: admissionregistration.k8s.io/v1
      kind: ValidatingWebhookConfiguration
      name: my-webhook
      metadata:
        labels:
          app: my-app
        annotations:
          description: "My webhook"
      rules:
        - apiGroups: [""]
          apiVersions: ["v1"]
          operations: ["CREATE"]
          resources: ["pods"]
          scope: "Namespaced"
```

### Key changes

1. The entire Kubernetes manifest now goes inside a `manifest` key
2. Labels and annotations must now be nested under `metadata`
3. The `spec` key is no longer used — all manifest fields go directly at the manifest level

:::note
The `metadata.labels` and `metadata.annotations` you provide are automatically merged with the labels and annotations managed by the library. The `metadata.name` field is ignored — the library generates the resource name based on its standard naming scheme.
:::
